# NAT 类型/层级探测

客户端首先需要连入STUN服务网络，获取多个服务节点的联系信息，其中包含建立安全 QUIC 所需的如 `SPKI`、`ECH` 公钥等。
详见 [cxio/p2p 项目](https://github.com/cxio/p2p)。

然后客户端就可以与这些服务节点建立连接，并请求探测服务。

> **技术栈：**
> 客户端与服务器间的通信采用 *QUIC 安全连接 & 底层 UDP Socket 复用* 模式，其中 QUIC 用于安全传输，底层裸 UDP 用于 NAT 映射探测。
> Go 语言实现，使用 quic-go 库，参考 `quic.Transport{Conn: udpConn}`, `Transport.ReadNonQUICPacket()` 等用法，外部传入 `net.UDPConn`。


## 准备

节点首先应当确认自己是否位于 UDP 被封禁的网域：尝试与服务节点建立 QUIC 连接，如果连接成功，则进入下一步，否则继续尝试。如果多次尝试都失败，那大概率 UDP 被封禁（`UDP Blocked`），NAT 探测无意义。

> **提示：**
> 如果已经与服务器建立TCP连接（确定在线），可直接请求其UDP监听地址并尝试连接。
> 因为网络分享的服务器节点信息并不完全可用（还有毒IP），所以该选项有更高的优先级。


## 预探测（STUN:Addr, Step.0）

当确认自己的 UDP 链路可用后，客户端向多个服务节点请求获取自身 UDP 地址（`STUN:Addr`），检查返回结果：

> **说明：**
> `STUN:Addr` 请求返回的是客户端的地址二元组（`IP:Port`），下面的地址即指此。
> 客户端需要从同一个 QUIC 连接（同一底层 UDPConn）向多个服务器请求 `STUN:Addr`，这是基本要求。
>
> 客户端向多个服务器请求 `STUN:Addr` 的成功返回数量应当不少于**3**个（可配置）。

- 如果多个服务器返回的客户端地址都不同，则确定为 `Sym-Like`，结束探测。
- 如果多个服务器返回的客户端地址有部分不同，也视为 `Sym-Like`，因为相同的部分可能只是网关的优化。结束探测。
- 如果所有服务器返回的客户端地址都相同，即视为 `非 Sym-Like`，进入下一步……

然后与本地地址（LocalAddr，含端口）对比：

- 相同（Y）：`Open Internet` | `UDP Firewall`，待进一步确认。
- 不同（N）：待正式探测，进一步判断……


## 正式探测（STUN:Cone）

客户端向任意一台服务节点请求 NAT 类型探测服务（`STUN:Cone`）。注意此时为 QUIC 安全连接。

> **提示：**
> 考虑可用性和可靠性，本流程可以尝试多次（如 `2~3` 次）。


### 客户端（Step.1）

客户端的 `STUN:Cone` 请求中包含如下数据：

1. Key32：会话密钥（32字节），用于构建会话标识（SN）。
2. Exclist：排除清单，包含节点自己近期（比如半小时）曾经连接过的远端服务器地址。

> **解释：**
> `NewHost` 消息需要一个近期未曾与客户端连接过的新IP，因此需要排除清单（`Exclist`）。
> 半个小时的时间窗口已经足够，因为没有哪个NAT映射会闲置这么久而不关闭。

服务端收到信息后，双方即可关闭 QUIC 安全连接，回退到该 QUIC 连接的底层普通 UDP 连接（UDPConn）上通讯。


### 会话标识

会话标识（SN）是一个有着内在构造规则的标识，用于识别每一次的 NAT 探测消息。

**SN**的构造规则如下（伪代码）：

```go
// Rnd16: 16字节随机序列。
// Rnd16[0]: 首字节高两位置零，标识非 QUIC 数据包。
// Rnd16[0]: 首字节的低1位用于标记消息发送源（服务端）：
// - 0: NewPort 同机新端口发送
// - 1: NewHost 新主机发送
// 设计：
// 明文会话标识尽可能不含特征魔数，避免数据包被定向销毁（丢弃）。

// 客户端：高2位清空。
// 非 QUIC 数据包，2位0值特征不明显（可接受）。
// 设计：
// 客户端构造的 SN 没有设置低位标记的逻辑。
Rnd16[0] = Rnd16[0] & 0x3F

// 服务端：高两位清空&低1为标记。
// from: NewPort | NewHost
Rnd16[0] = Rnd16[0] & 0x3E | from

// 客户端&服务端共用。
// LocalAddr: 为公网映射地址（对端可通过 conn.RemoteAddr() 获取）。
// TmpN: 变长随机字节序列，用于隐藏 SN 的长度特征。长度：464 ~ 1024
// 前段固定 16 + 32 = 48 字节。
SN = Rnd16 + HMAC_SHA256(Key32, Rnd16 + LocalAddr + TmpN) + TmpN
```

> #### 附：SN 验证
> - 从 SN 提取各片段：Rnd16, Hash32, TmpN。
> - 提取对端地址（即 SN.LocalAddr = conn.RemoteAddr()），验算SN合法性：HMAC_SHA256(...) == Hash32。


### 服务器（Step.2）

服务端获取客户端发来的信息，然后执行如下操作：

- `NewPort`: 用一个新的随机端口向客户端发送消息，数据为即时构造的 SN。
- `NewHost`: 从本机的另一个新IP或请求另一个服务器向客户端发送消息，数据 SN 即时构造。

> **实现：**
> NewPort 和 NewHost 应双路并发执行，客户端统一超时计时。


#### 受托服务器

如果是请求另一个服务节点协助执行 `NewHost`（委托发包），会向其提供必要的客户端信息（`Notice`）：

- 客户端公网映射地址（`IP:Port`）。
- 客户端的会话密钥封装 `SHA256( Key32 )`。

此时不会向受托服务器传递原始的客户端会话密钥，以强化安全性（冗余，但低成本）。

**受托配合**：受托服务器会执行 `NewHost` 操作：向目标客户端发送纯 UDP 消息，消息内容为相同规则即时构造的 `SN`。

> **注意：**
> 如果是源服务器从自己本机的一个新IP发送 `NewHost`，也需要用封装之后的会话密钥构造 SN。
> 因为客户端会借助于 `NewHost` 标识来判断会话密钥的实际值。


#### 消息发送

服务器通过普通的裸 UDP 连接发送消息，需要实现冗余发送逻辑。考虑被利用作为 DDoS 攻击的可能性，冗余发送的次数应尽量低。

设计发送次数为**3**次，间隔时间为：`200ms, 400 ~ 800ms`。累计时长 `600ms ~ 1s`。服务器按规则发送即可，不用等待客户端回应（实际上也没有回应）。

> **注意：**
> 每一次发送的 SN 都是即时新建的，以避免链路中间件的优化合并或丢弃。


#### 源服务器安全

无信任委托发包，可能被恶意的源服务器利用，创建 DDoS 攻击，因此这里需要一个安全防范或缓解措施。

在P2P的环境下，设计一种可信机制会很复杂。考虑简单性和效率，我们采用**工作量代价**来进行 DDoS 缓解：源服务器委托时需要附带一个工作量证明（`Equi-X`）。

委托发送消息的冗余度并不高（共3次），因此源服务器通常需要委托 `2~3` 个服务节点协助：

1. 源服务器向受托服务器发送 NewHost 协助请求。
2. 如果受托服务器接受请求，会返回一个挑战值 `challengeSeed`，32字节随机序列。
3. 源服务器执行运算：`solution, nonce := equix.Solve(challengeSeed)` 找到解，提交。
4. 受托服务器验证解，如果正确，即执行协助。

> **实现参考：**
> 受托服务器创建 challengeSeed = `SHA256(globalSeed + conn.RemoteAddr())`。
> 这样就不需要在受托服务器上存储任何状态，验证时直接计算即可。
>
> Equi-X 使用 CGO 封装官方 C++ 库（`github.com/tevador/equix`），实现成熟且效率较高。


### 客户端（Step.3）

客户端读取收到的消息，提取发送源（`NewPort`|`NewHost`），并根据规则验证 SN 的有效性。

> **注意：**
> 如果是 NewHost 消息，HMAC 的密钥应为：`SHA256( Key32 )`。

如果核验通过，则为有效的探测包。因为服务端发包较少，且历时很短（理论上 1s，实际上可能 2~3s），故不设计客户端回应。


### 综合判断（Step.4）

客户端根据 `NewPort` 和 `NewHost` 两个连入的情况，综合判断自身 NAT 类型或所在网域。

**NewPort**:
- 收到 => `RC | FullC`。**注**：`FullC` 在 NewHost 段确认&覆盖。
- 超时 => `P-RC | Sym-Like` => `P-RC`。**注**：`Sym-Like` 已在预探测中确认并排除。

**NewHost**:
- 收到 + 预探测.N => `FullC`。
- 收到 + 预探测.Y => `Open Internet`，即 `Public`。
- 超时 + 预探测.Y => `UDP Firewall` 网域。

> **提示：**
> 只要 NewHost 能收到消息，NewPort 的超时可以无需理会。


### 附：判断矩阵

| NewPort 收到 | NewHost 收到 | 与本地地址相同 | 结果 |
|:---:|:---:|:---:|------|
| - | Y | N | Full Cone |
| Y | N | N | RC |
| N | N | N | P-RC |
| - | Y | Y | Open Internet（Public） |
| - | N | Y | UDP Firewall |

**说明：**
- `N` 表示否定（No）。
- `Y` 表示肯定（Yes）。
- `-` 表示无需考虑，N/Y 皆可。


### 附：客户端超时

- **对齐时钟**：客户端在发出 STUN:Cone 请求后，其等待的超时综合考虑，设置为**5**秒。
- **静默处理**：如果在 5 秒内客户端一个包都没收到，即可断定该探测项（NewPort 或 NewHost）为失败。
