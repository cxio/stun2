# 公网地址获取：`STUN:Addr`

客户端连接服务器后，首先需要请求对端告知自己在该连接上的 NAT 公网映射地址。此即最基础的 `STUN:Addr` 服务。


## 定位

- 控制面：在**已经建立**的 QUIC 安全连接上请求/响应。QUIC 为 Stream 模式。
- 观测对象：服务器从**当前这条** QUIC 连接所对应的 UDP 对端提取源地址。

> **双栈客户端：**
> 根据客户端所在网络环境，系统可能会优先使用 IPv6 链路。
> 如果想要探测 IPv4 链路的 NAT 映射，客户端需要显式使用 IPv4 地址访问服务器。


## 地址格式

连接可能走 IPv6，也可能走 IPv4。返回的 IP 统一为 IPv6 形式：IPv4 使用 IPv4-mapped 编码（`::ffff:IPv4`）；原生 IPv6 原样返回。

端口简单的两字节整数，是服务器观测到的客户端 UDP 源端口。


## 请求与响应

客户端与服务器通过 QUIC 方式连接，简单的发送请求即可。不论底层的 Socket 是基于 `net.DialUDP` 还是 `net.ListenUDP` 创建。

**请求：**

- Version: 版本号（初始值 1）。
- Request: STUN:Addr

**响应：**

- Version: 与请求相同的版本语义。
- IP:     观测到的客户端公网 IP（返回 IPv6 形式）。
- Port:   观测到的客户端 UDP 源端口。

服务器总能从当前连接读出对端地址，因此总能正确响应，除非 `Version` 不符，服务器会返回错误提示。


## 用途

- **全等比较**：与本机 Socket 源地址全等比较，用于判断是否为公网直连（`Open Internet` | `UDP Firewall`）。
- **IP 比较**：需要忽略端口的情形，比如确认出口地址是否仍是同一公网 IP（如手机从 WIFI 切换到移动网络）。
- **端口比较**：主要用于 NAT 内网节点探知自己的出口 NAT 映射类型是否为 `Symmetric Like`（多个 NAT 映射端口各自不同）。
