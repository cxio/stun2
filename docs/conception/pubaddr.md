# 公网地址获取：`STUN:Addr`

客户端连接服务器后，首先需要请求对端告知自己在该连接上的 NAT 公网映射地址。此即最基础的 `STUN:Addr` 服务。


## 定位

- 控制面：在**已经建立**的 QUIC 安全连接上请求/响应。
- 观测对象：服务器从**当前这条** QUIC 连接所对应的 UDP 对端提取源地址。

**注意**：在双栈主机上，IPv4 连接与 IPv6 连接是两条独立路径，应分别请求；一次请求只反映当前连接的地址族。


## 地址格式

连接可能走 IPv6，也可能走 IPv4。返回的 IP 统一为 IPv6 形式：IPv4 使用 IPv4-mapped 编码（`::ffff:IPv4`）；原生 IPv6 原样返回。

端口简单的两字节整数，是服务器观测到的客户端 UDP 源端口。


## 请求与响应

客户端在当前已有的 QUIC 连接上发送请求即可，不论底层创建的 Socket 是基于 `net.DialUPD` 还是 `net.ListenUDP`。

**请求：**

- Version: 版本号（初始值 1）。
- Request: STUN:Addr

**响应：**

- Version: 与请求相同的版本语义。
- IP:     观测到的客户端公网 IP（返回 IPv6 形式）。
- Port:   观测到的客户端 UDP 源端口。

**服务器**：总能从当前连接读出对端地址，因此本服务*没有*拒服条件，除非 `Version` 不符。

**客户端超时**：本服务只有一次往返，客户端单次超时默认 **4** 秒（可配置）。


## 用途

- **全等比较**：与本地数据出口地址全等比较，用于判断是否为公网直连（`Open Internet` | `UDP Firewall`）。
- **IP 比较**：需要忽略端口的情形，比如确认出口地址是否仍是同一公网 IP（比如手机从 WIFI 切换到移动网络）。

> **注意：**
> 比较前两个地址需规范到同一形式，如都为 IPv4 或 IPv6（IPv4 => IPv4-mapped）。
